# FinFlow KB metadata: controlled values

Every article's frontmatter uses only these values. Add a new value here first, with a reason, before using it in an article.

## topic (one per category, matches the category name)

| Value | Category |
|---|---|
| account_suspension | Account suspension (restricted accounts) |
| refund_timelines | Refund timelines |
| transaction_disputes | Transaction disputes |
| failed_payments | Failed payments |
| kyc_verification | KYC verification |
| fee_explanations | Fee explanations |
| two_factor_authentication | Two-factor authentication |

## issue_type

| Value | Use when |
|---|---|
| process | The article explains how something works or what happens in order (cancelling, disputing, verifying) |
| troubleshooting | The article starts from something going wrong and explains why (a failed payment) |
| informational | The article explains a policy or set of facts, with no process or failure at its centre (fees) |

## resolution_type

| Value | Use when |
|---|---|
| self-service | The customer can resolve it themselves |
| agent-required | The support team has to act |
| automatic | FinFlow resolves it with no action from the customer or support |

## severity

| Value | Use when |
|---|---|
| high | Money or account access is at risk, or the customer can't act |
| medium | Money is delayed or the customer is blocked but has a path forward |
| low | The customer needs information, with no money or access at risk |

## customer_segment

| Value | Use when |
|---|---|
| both | Applies to all customers (every v1 article) |
